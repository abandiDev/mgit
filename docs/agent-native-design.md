# mgit: Agent-Native Design

*Design exploration, 2026-07-08. Produced by a multi-agent workflow: 3 codebase readers → 6 dimension designers (working memory, feature branching, agent interface, multi-agent handoff, cross-repo timeline, harness integration) → 3-lens judge panel (agent ergonomics, simplicity, product coherence) → synthesis.*

**Status: implemented (all three phases), 2026-07-08.** New modules: `core/memory.py`, `core/brief.py`, `core/checkpoint.py`, `cli/checkpoint.py`, `utils/output.py`. New commands: `feature brief/note/plan/log/fork/tree`, `checkpoint save/restore/list/show/delete`, `upgrade`. One deviation from the plan: the console-script entry point in pyproject.toml pointed at `main` instead of the `cli()` wrapper, so the exit-code contract required fixing that (the error handler had been dead code). 180 tests pass (117 pre-existing + 63 new).

## Vision

mgit becomes the agent-native workspace layer git is missing: every feature carries a continuously maintained **working memory** (an auto-populated journal plus a small plan file) that a fresh agent session recovers with one cheap `mgit feature brief` call — and that Claude Code loads automatically via a generated CLAUDE.md sitting at the worktree-ancestor directory. Features **fork like branches, but across all enrolled repos at once**, with pinned base SHAs and inherited memory; later, ref-anchored cross-repo **checkpoints** give agents a save-point and an undo button spanning the whole feature.

Two invariants anchor everything:

- **Git stays the sole source of truth for code state.** Dirty flags, ahead counts, last-commit subjects are computed live at read time, never stored — so a raw `git commit` inside a worktree can never make stored state lie.
- **mgit owns exactly one new substrate**: plain files under `.mgit/` for intent, history, and lineage. No daemons, no locking infra, no databases.

## Core data model

**Existing, unchanged:** `.mgit/config.toml`, `.mgit/active`, `.mgit/worktrees/<feature>/<repo>/` with sandbox branch `mgit/<feature>` (branch naming pinned by 117 tests — untouched).

**Extended:** `.mgit/features/<name>.toml` gains `parent = "<feature>"` under `[feature]`, a `[fork_base]` table (repo → SHA pinned at fork time), and later `[wip_from]` (repo → snapshot-commit SHA). `FeatureInfo` gains `parent`, `fork_base`, `wip_from`; serializers omit-when-empty and read via `.get()` so old feature files keep loading.

**New — per-feature memory sidecar** at `.mgit/features/<name>/` (a directory *beside* the untouched flat TOML, so `FeatureManager.list()`'s glob and all pinned tests survive):

1. **`memory.toml`** — `goal`, `status`, `next_steps = []`, `open_questions = []`, `updated_at` (ISO-8601 UTC). Whole-file overwrite via write-temp + `os.replace` (atomic).
2. **`journal.jsonl`** — *the* single event log (no global events file, no sessions dir, no separate timeline). Append-only, one JSON object per line, line-atomic on local POSIX:
   ```json
   {"ts": "...", "actor": "agent"|"mgit", "type": "note"|"decision"|"question"|"handoff"|"event",
    "text": "...", "event": "created|repo_enrolled|materialized|synced|switched|commit|push|forked|checkpoint|restored|...",
    "repo": "...", "meta": {"sha": "...", "subject": "...", "carried": true}}
   ```

**New — generated ambient brief:** `.mgit/worktrees/<feature>/CLAUDE.md` (+ identical `AGENT.md`). This directory is an ancestor of every worktree but outside every git repo, so Claude Code's recursive memory loading picks it up with **zero install, zero tool calls, zero git pollution**. It's a derived artifact — rendered by the same function as `feature brief`, regenerated atomically on every `FeatureManager` mutation. Header: "generated by mgit — edit via `mgit feature note/plan`".

**New (Phase 3) — checkpoints:** `.mgit/checkpoints/<feature>/cp-NNNN.toml` (`[checkpoint]` id/label/created_at + `[repos.<name>]` head/snapshot/branch/dirty) with a sibling `cp-NNNN.memory.toml` so notes rewind with code. Snapshot commits are created **non-destructively** via temp-index (`GIT_INDEX_FILE`) write-tree/commit-tree — never stash, working tree untouched — and pinned by `refs/mgit/checkpoint/<feature>/<cp-id>` in each repo's shared ref store (visible from all worktrees, GC-immune, never pushed).

**Cross-cutting invariants:**
- **Cleanup contract:** `feature delete` removes the sidecar dir, checkpoints dir, generated CLAUDE.md, and `refs/mgit/checkpoint/<name>/*` per repo; `remove-repo` prunes that repo's refs.
- **Name validation:** feature names reject `/` (and ref-hostile chars) at `FeatureManager.create` — shared prerequisite for branch refs, checkpoint refs, and per-feature dirs (flagged independently by three designers).
- **Agent contract:** exit codes 0 success / 1 bulk-partial / 2 domain (`MgitError`) / 3 usage / 4 internal; JSON payloads carry `mgit_schema: 1` with an additive-only policy.

## Phase 1 — Working Memory + Feature Fork (the core ask, shippable alone)

**Goal:** every feature continuously maintains where the work is — auto-journaled at existing lifecycle choke points with **zero agent discipline**, enriched by cheap note/plan commands, recovered by one call — and features can branch.

### Commands

| Command | What |
|---|---|
| `mgit feature brief [-f NAME] [--json] [--full]` | THE re-orientation call: memory.toml + journal tail(10) + live git facts per repo (materialized?, dirty, ahead-of-target count, last commit subject), ~40 lines, with an "updated Xm ago" staleness line |
| `mgit feature note TEXT [--type note\|decision\|question\|handoff]` | One O_APPEND journal line; flags-only, no prompts |
| `mgit feature plan [--goal] [--status] [--next ...] [--add-next] [--done N] [--ask] [--resolve N]` | Update memory.toml; every overwrite also journals a `plan_updated` event so history is never lost |
| `mgit feature log [-n 20] [--json] [--type TYPE]` | Read the journal beyond the tail; skips corrupt lines, reports error count |
| `mgit feature fork CHILD [--from PARENT] [--materialize] [--branch TARGET]` | Pin each repo's current `mgit/<parent>` tip (or origin HEAD if unmaterialized) into child `[fork_base]`, set parent lineage, copy enrollment, seed child memory from parent's, set child active |
| `mgit feature tree [--json]` | ASCII ancestry from parent fields; `*` marks active |
| `mgit context` (additive) | `active_feature` gains a memory block {goal, status, next_steps, open_questions, updated_at, journal_tail(5)}; `features[]` gain {parent, status, updated_at} |

### Key changes

- `models/types.py`: new `MemoryState` dataclass; `FeatureInfo` gains `parent`/`fork_base`.
- `core/config.py`: round-trip new fields omit-when-empty.
- **New `core/memory.py`** (~150 lines): `load_state`/`save_state` (temp+replace), `append_event`, `journal_tail` (tolerant of bad lines), `build_brief` (every git call guarded, degrades to "unknown").
- `core/feature.py`: auto-journal at every choke point — `create`→`created`, `start`→`repo_enrolled`, `materialize`→`materialized` (with carried flag), `sync`→`synced`, `switch`→`switched`, `delete`→rmtree sidecar; new `fork()`; `materialize()` passes `start_point=fork_base.get(repo)`.
- `core/repo.py`: `add_worktree(..., start_point=None)` → `git worktree add -b <branch> <path> <start_point>`; `ahead_behind()` helper.
- `cli/bulk.py`: after commit/push, append a journal event per SUCCESS repo (~15 lines).
- `core/workspace.py` AGENT_MD_TEMPLATE + README: document the ritual (brief first; note decisions; plan --status/--done before ending).

**Effort:** medium (~1–2 weeks; two new modules, surgical edits to five files, all testable with existing real-git fixtures).

## Phase 2 — Ambient Delivery + Agent Contract Hardening

**Goal:** memory reaches agents with zero tool calls, and every mgit invocation becomes machine-safe.

- **(automatic)** `.mgit/worktrees/<feature>/CLAUDE.md` + `AGENT.md` regenerated on every FeatureManager mutation — Claude Code auto-loads it in any session launched inside a worktree.
- `mgit context` / `feature brief/log` / all bulk ops gain `--json` with the `mgit_schema: 1` envelope; `BulkResult` serialization is just plumbing over existing dataclasses.
- Typed errors: `MgitError` → JSON error object + exit 2; usage → 3; internal → 4; **never a Python traceback** (fixes a verified traceback leak in `cli/__init__.py`).
- Non-TTY safety: carry prompts raise a clean `MgitError` telling the agent to pass `--carry`/`--no-carry` instead of hanging on `click.confirm`.
- `context` gains `-f` scoping + per-worktree branch/dirty/ahead-behind (null = unknown; never auto-fetch — stays cheap and side-effect-free).

**Effort:** small-medium (~1 week).

## Phase 3 — Cross-Repo Checkpoints + WIP-Carrying Fork

**Goal:** one checkpoint concept spanning the whole feature — non-destructive save, restore with a **mandatory** pre-restore safety checkpoint, memory snapshotted alongside code.

- `mgit checkpoint save [--label TEXT]` — per materialized repo: pin HEAD; if dirty, temp-index snapshot commit (working tree untouched); anchor `refs/mgit/checkpoint/...`; write manifest + memory copy.
- `mgit checkpoint restore ID` — always auto-saves a safety checkpoint first (no `--no-backup` escape hatch in v1), then `git clean -fd` → `reset --hard <snapshot>` → `reset <head>` (WIP re-materializes as dirty files); restores the checkpointed memory.
- `mgit checkpoint list/show/delete` — manifests + `update-ref -d` so snapshots become GC-able.
- `mgit feature fork CHILD --carry-wip` — snapshot the parent's dirty worktrees via the same machinery, applied once at child materialize (conflict-free by construction).
- `mgit feature log --commits` — journal events interleaved with sandbox-branch commits across repos, merged by timestamp: "one story instead of N git logs", derived from git, never authoritative.

**Effort:** large (~2–3 weeks; the snapshot/restore paths need the most careful testing — deliberately last, after the memory/fork substrate is proven).

## Deliberately cut (with why)

- **Claim/release/TTL session locks** — all three judges: honor-system locks agents ignore; TTL heuristics dangerous both ways; worktree-per-feature isolation already covers the real contention unit. Journal visibility + one-agent-per-feature convention in AGENT.md instead.
- **Separate handoff/resume subsystem + `.mgit/sessions/`** — duplicates the memory system under different names; survives as journal type `handoff` plus brief's live delta computation.
- **Global `events.jsonl` + `mgit events --since` + flock/seq** — one journal substrate only; would introduce mgit's first locking infra for a polling pattern nobody asked for.
- **Global `--json` on every command + `mgit schema`** — targeted `--json` on the agent-consumed commands delivers the contract without freezing every command's output forever.
- **`[hooks]` config tables (arbitrary shell on post_commit/post_sync)** — grows config-driven shell-execution blast radius with no current consumer.
- **`mgit agent install` (writing `.claude/settings.json`)** — read-modify-write of another tool's config, coupled to a hook schema that drifts across Claude Code versions; the worktree-ancestor CLAUDE.md delivers the injection harness-agnostically. Revisit as opt-in.
- **`feature publish`/`feature checks` (gh-based cross-repo PRs + CI)** — legitimate future milestone, not a founding pillar; GitHub-only coupling, merged-PR idempotency traps.
- **`feature merge`** — inherently non-atomic across repos; a half-merged feature is the worst state to hand a fresh context window. Agents can merge per-repo with plain git; checkpoints make that safe to attempt.
- **`feature diff <a> <b>`** — per-repo `git diff` wearing an mgit costume; deferred until forked variants prove common (`feature tree` stays — lineage is mgit-owned data git can't show).
- **Checkpoint-as-commit-all** — exactly one checkpoint noun; "commit everything" already exists as `mgit commit -f .`.
- **Repo dependency graph + wave-ordered push** — build orchestration outside the workspace mental model; manually-maintained graph data rots.

## Decisions (owner, 2026-07-08)

1. **Command name:** `feature fork` is canonical. Avoids overloading "branch" (mgit already has target branches and sandbox branches, and fork takes a `--branch TARGET` flag).
2. **Fork's remote target:** child defaults to its own name — separate PRs per variant, sibling forks can never collide on push. `--branch` overrides when a variant should fold back.
3. **Exit codes:** migrate freely now. Full table ships: 0 ok / 1 bulk-partial / 2 domain / 3 usage / 4 internal. Release-note the usage-error move from 1 → 3.
4. **Journal retention:** append-only forever. `brief` reads only the tail; `delete` removes the sidecar. Revisit compaction only if real journals get huge.
5. **Brief's ahead-count base:** hybrid — use `origin/<target>` when the remote-tracking ref exists locally, silently fall back to local `default_branch` tip. Never fetch; label which base was used.
6. **Fork + checkpoints:** SHA-pin only. Fork stays decoupled from the checkpoint subsystem; agents wanting WIP provenance run `checkpoint save` first or use `--carry-wip`.
7. **Concurrent `plan` writes:** last-writer-wins, documented one-writer-per-feature in AGENT.md. The journal's `plan_updated` events make any lost update recoverable. No locking code.
8. **In-flight diff:** fold the non-TTY prompt guard in *before* it merges — if stdin isn't a TTY (or `--json`), raise a clean `MgitError` instructing `--carry`/`--no-carry` instead of `click.confirm`.

## How harnesses use it automatically

Four layers, from zero-config to fully programmatic. The base layers work even when the harness has never heard of mgit.

### Layer 0 — ambient context files (zero config, any harness)

The generated brief lands at `.mgit/worktrees/<feature>/` in two spellings:

- **`CLAUDE.md`** — Claude Code walks up from the working directory loading CLAUDE.md files from ancestor directories. A session launched anywhere inside a worktree (`.mgit/worktrees/<feature>/<repo>/…`) auto-loads the feature's memory before the first prompt.
- **`AGENTS.md`** — the cross-tool standard (agents.md) that Codex, OpenCode, Amp, Cursor, and Gemini CLI read, most of them also walking ancestor directories. (Note: mgit's workspace-root file is currently `AGENT.md`, singular — emit `AGENTS.md` alongside or rename to match the standard.)

The file is a snapshot from the last mgit mutation, so it also serves as a **bootstrap**: its content tells an mgit-naive agent what mgit is, that live state comes from `mgit feature brief`, and which commands maintain the memory (`note`, `plan`, `commit -f .`). Even a harness that only understands "read AGENTS.md" gets pulled into the ritual.

A typical session, no configuration anywhere: harness starts in a worktree → ambient file injects goal/status/next-steps/journal-tail → agent runs `feature brief` for live git facts → works, committing via `mgit commit -f .` (journal auto-populates) → records decisions with `feature note` → session dies at context exhaustion → the next session re-orients the same way, losing nothing.

### Layer 1 — session hooks (opt-in, documented recipes — deliberately not `mgit agent install`)

Harnesses with lifecycle hooks can trade the snapshot for live state:

- **Claude Code:** a `SessionStart` hook running `mgit feature brief` injects fresh state each session; a `Stop` hook running `mgit feature note --type note "$(summary)"` makes memory-writing zero-discipline.
- **Codex / OpenCode:** equivalent wiring via `notify`/plugin mechanisms where available.

These stay *documented recipes* in AGENT.md/README, not code that mutates another tool's config file (cut list: schema drift, shared-file read-modify-write).

### Layer 2 — machine contract (orchestrators and wrapper scripts)

For harnesses driving mgit programmatically rather than ambiently: `mgit context --json` is the single discovery call (repos, features, lineage, memory block, active feature); `feature brief --json` / `feature log --json` for per-feature depth; the frozen exit-code table and `mgit_schema: 1` envelope make every call parseable and every failure machine-actionable. A multi-agent orchestrator can assign one feature per agent, fork variants for parallel approaches, and diff their journals — without any prompt engineering.

### Layer 3 — auto-capture (works regardless of harness)

The journal baseline populates from normal command use — `start`, `materialize`, `sync`, `commit`, `push` all append events. A harness needs to know *nothing* about the memory system for the memory to exist; the agent-authored layers (`note`, `plan`) only make it richer.

**Future (deferred):** an MCP server exposing mgit as typed tools — worth revisiting once the CLI contract has proven its shape; the `--json` surface is the substrate it would wrap.

## Upgrade path: existing workspaces vs new installs

**New installs:** nothing special. `mgit init` writes the updated AGENT.md (working-memory ritual, fork/checkpoint docs, exit-code table); sidecar dirs, journals, and worktree briefs appear as features are created. Day-one users never see a world without memory.

**Existing workspaces upgrade in place — no migration step, everything is lazy and additive:**

- **Feature TOMLs:** old files load unchanged (new fields read via `.get()`, written omit-when-empty). New fields only appear in a file after a write that sets them (i.e., a fork).
- **Memory sidecar:** created lazily on first journal event or `plan` write. `feature brief` on a legacy feature degrades gracefully — "(no memory recorded yet)" plus live git facts; the journal starts recording from that moment.
- **Worktree CLAUDE.md/AGENTS.md:** appears at the next `FeatureManager` mutation touching that feature, or on demand via `feature brief --refresh`.
- **Workspace-root AGENT.md:** the one thing that does *not* self-heal — it is written once at init, and `Workspace.init` refuses existing workspaces (`workspace.py:110`). Ship a tiny idempotent **`mgit upgrade`**: regenerates AGENT.md from the current template (backing up a locally modified copy to `AGENT.md.bak`), regenerates all worktree briefs, and prints what changed. It also becomes the natural home for any future on-disk migration, so the "no migration needed" story stays true by construction.
- **Behavioral release notes (the only breaks):** usage errors exit 3 instead of 1 (decision 3); interactive carry prompts refuse non-TTY stdin with a clean error instead of hanging.
- **Edge case:** pre-existing feature names containing `/` (validation only applies at create). `feature brief`/`upgrade` should warn that such features can't use checkpoints (ref-path collision) and suggest a rename.

**Downgrade caveat:** an older mgit reading a post-upgrade workspace works (extra TOML keys and sidecar dirs are ignored), but if old code *rewrites* a feature file it silently drops `parent`/`fork_base`. Not worth machinery — a line in the release notes.
